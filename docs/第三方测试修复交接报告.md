### 3.2 关键根因与方案

1. **状态清理逻辑被旁路**（P1-001）：把"副作用"（滚动锁）放在调用方，而该调用方不是唯一入口。
   → 下沉到唯一的模态工厂，并用引用计数表达"还有没有别的模态持有锁"。
2. **默认路径依赖新版本 API**（P1-002 / 图片渲染钩子）：模板无法 try/catch，一旦字段不存在就整体失败。
   → 显式版本能力探测；不支持时给**确定行为**（回退或明确报错），并逐版本回归。
3. **按字节数判断 rune 长度**（P1-003）：`len` 与 `slicestr` 的计数单位不同。
   → 统一用 `countrunes` 判断后再截断，并抽出 helper 避免再犯。
4. **颜色 token 用途混用**（P2-003）：同一变量同时用作文字色与背景色，无法同时满足两种对比度要求。
   → 按用途拆分 token（背景 / 实心底 / 文字），并用浏览器度量固化。
5. **测试断言形态漂移**（多条 TEST-DEFECT）：正则只认一种引号形态、真空 `all()`、
   `n >= 0`、路径不存在导致空转。
   → 统一原则：**"检查不到任何对象"必须是失败**，且断言必须能对"故意注入的缺陷"报警。
