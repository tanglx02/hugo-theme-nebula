### 1.1 判定为「废弃脚本」的 4 个文件（逐个核实，非按名字删）

| 脚本 | 零引用证据 | 失效原因 | 判定 |
| --- | --- | --- | --- |
| `tools/gen_covers.py` | 仓库内全库检索 0 命中 | 输出路径写死为 **仓库内** `myblog/static/img/cover`，而 `myblog` 已移出仓库（现存于父目录，且非 git 仓库）；生成物是**站点封面**，非主题交付物 | **删除** |
| `tools/sync_theme.py` | 全库 0 命中 | 同上一文件：源 `myblog/themes/hugo-theme-nebula` → 目标 `hugo-theme-nebula` 的路径在仓库内均不存在，**已无法执行**；该流程是早期"站点内调试 → 同步回仓库"的一次性搬运，现已直接在本仓库开发 | **删除** |
| `tools/inject_v107.py` | 全库 0 命中（未被 `run_ci_injections.sh` 调用） | v1.0.7 阶段的临时注入脚本，已被 `inject_v109.py`（文档化、`--revert`/`--list`）取代 | **删除** |
| `tools/inject_v108.py` | 全库 0 命中 | 同上，v1.0.8 阶段遗留 | **删除** |

> 反例（**保留**）：`tools/screenshot.py` 同样零"脚本间"引用，但它产出
> `docs/screenshots/*.png`——README 首屏直接引用这些图片，属**交付物生成器**，
> 且有明确用法。**本轮保留并补文档**，不删。
>
> 其余 50+ 个 `tools/*.py` 均有引用（CI 步骤 / 文档 / 其他脚本），**一律保留**。

## 2. 清理动作

- 只删除上表标记为「删除」的条目；被忽略目录内的删除使用系统删除（不进回收站的内容
  均为可重建产物，且均在 `.gitignore` 内）。
- **不执行** `git clean -fdx`、**不执行** `git reset --hard`。
- `exampleSite/_ms-verify-multisec-*.toml` 的根因（`verify_multisection` 失败路径
  未清理）本轮一并修复。

| `public-en/` `public-zh-tw/` | 各 5.0 MB | **已删除** | 多语言构建产物 |
| `public-iso/` `public-v0.128.0` ~ `v0.167.0` | 27 MB | **已删除** | 本轮跨版本验证产物 |

| `tools/html_inventory.json` | — | **已删除** | `html_inventory.py` 重建 |
