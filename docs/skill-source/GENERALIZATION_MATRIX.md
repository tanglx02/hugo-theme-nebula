# GENERALIZATION_MATRIX — 经验的可迁移性分级矩阵

> **用途**：为制作**通用 Hugo 主题开发 Skill** 提供"哪些经验能进通用规则、哪些不能"的判据。
> **一句话判据**：**能回答"为什么"的是方法（可迁移）；只能回答"是什么"的是实例（专有）。**
>
> **红线**：**不得把 Nebula 的专有做法写成所有 Hugo 主题的强制规则。**
> 本文件明确区分三档，通用 Skill 只应采纳**第 1 档**（并在第 2 档按条件启用）。

---

## 0. 三档分级定义

| 档位 | 名称 | 定义 | 进通用 Skill？ |
| --- | --- | --- | --- |
| **A** | **普遍适用的技术规则** | 由 Hugo / Go template / 浏览器 / HTTP 的**固有语义**决定；任何 Hugo 主题都会遇到 | **必须进**（作为硬规则） |
| **B** | **结构或部署相关的规则** | 只在**特定主题结构 / 部署方式 / 内容形态**下成立；换结构可能不适用 | **条件进**（写成"若…则…"） |
| **C** | **Nebula 专属** | 具体实现、配置键、文件名、问题编号、数值、品牌 | **不进**（仅作教学案例） |

---

## 1. 档位 A — 普遍适用的技术规则

### A1. 模板语言固有语义

| 规则 | 为什么普遍 | Nebula 中的落点（仅作例证） |
| --- | --- | --- |
| **`default` 会吞掉显式 `false`**；需显式区分"未设置"与"设为 false" | Go template `default` 判空/零值，`false` 是 bool 零值 | `util/bool-param.html` |
| **partial 返回值会被包成 `template.HTML`（字符串）**，直接返回 bool 会被 `if` 恒判真 | Hugo 模板管道语义 | 同上（故返回 `dict`） |
| **`slicestr` 按 rune 计数，越界会 panic 并终止整站构建**；`len` 返回**字节数** | Go 的字符串是字节序列；Hugo 的 `slicestr` 按 rune | `util/slice-runes.html` |
| **`cond` 会先求值两个分支**，不能用于"能力探测"式条件访问 | Go template `cond` 实现 | `util/locale.html` |
| **`isset` 对驼峰键不可靠**（Params 键统一小写存储） | Hugo params 存储语义 | `bool-param.html` 改用遍历+小写比较 |

### A2. 跨版本能力探测

| 规则 | 为什么普遍 |
| --- | --- |
| **先探测能力再用**，而不是硬编码版本号 | 任何长期维护的主题都要跨 Hugo 版本 |
| **探测靠 `hugo.Version` 解析 major/minor**，并配 `if/else` 分支 | 规避 API 差异 |
| **旧版本要么回退（打 WARN），要么明确报错**，绝不静默降级 | 通用可维护性要求 |

> ⚠️ **不要**把 Nebula 的具体阈值（`resources.Publish`=0.166、`.Locale`=0.158）写成通用常量——
> 那是**当时的事实**，会随 Hugo 演进过期。通用 Skill 只保留"探测"这个方法。

### A3. 安全与健壮性

| 规则 | 为什么普遍 |
| --- | --- |
| **URL scheme 校验要在"被信任的源头"做**（调用方常用 `safeURL`） | 任何输出链接的主题都涉及 |
| **判定前剥除空白/控制字符**（浏览器会忽略 `"java\nscript:"` 中的换行） | 通用绕过手法 |
| **极端输入（空/单字符/CJK/emoji/空白）不得中断整站构建** | 任何主题都可能遇到 |
| **空值/零值字段宁可省略，也不输出 null / `0001-01-01`** | 结构化数据通用要求 |

### A4. 测试与流程（与方法学有关，与主题无关）

| 规则 | 为什么普遍 |
| --- | --- |
| **退出码约定：断言失败 / 依赖缺失 / 零用例执行 = 非零退出** | 否则 CI 门禁失去意义 |
| **重要断言必须故障注入自证"坏了一定变红"** | 防假绿 |
| **注入必须够强**（子串匹配断言不能只在子串周围加字） | 否则"注入没红"会被误读为"假绿" |
| **异步页面一次快照**（判定与报错信息取自同一时刻） | 防自相矛盾假红 |
| **度量前禁用 CSS 过渡 / 用相对判据 / 有界重试替代固定 sleep** | 防 flaky |
| **输入非空断言 + 零用例即失败** | 防空洞真 |
| **冻结候选 SHA + 证据绑定该 SHA；换 SHA 必须重新界定** | 任何交付流程通用 |
| **区分"产品 bug / 测试脚本 bug / 环境问题"** | 通用排障 |
| **独立测试只测不改；无授权不合并** | 通用交接纪律 |
| **未验证项必须登记，不得冒充已验** | 通用诚实性要求 |

## 2. 档位 B — 结构或部署相关（条件成立才适用）

> 写法必须是 **"若主题具备 X 结构 / 采用 Y 部署，则应 Z"**，而非无条件的"必须 Z"。

| 规则 | 适用条件 | 不适用的情况 |
| --- | --- | --- |
| **构建产物 inventory 作为全站审计真值，sitemap 只作 SEO 检查** | 主题有**多类型页面**（列表/分页/term/归档/别名）且需要全站审计 | 单页主题、无需全站审计的轻量主题 |
| **分页发现交叉验证 + alias 单独静态验证** | 主题使用分页与 alias | 无分页/无 alias |
| **`baseURL` 子目录部署（`/blog/`）路径归一** | 主题要支持子目录部署 | 仅根域部署 |
| **i18n 日期在构建期完成**（索引存机器+展示双字段） | 主题有**客户端搜索/索引**且需多语言 | 无客户端搜索、纯服务端渲染 |
| **客户端搜索的索引契约（模式/分片/竞态/失败语义）** | 主题提供**客户端全文搜索** | 无搜索 |
| **Modal 无障碍工厂（focus trap / inert / 焦点归还 / 滚动锁引用计数）** | 主题有**浮层**（搜索弹窗/灯箱/抽屉） | 无浮层的主题 |
| **触控目标 ≥24px（2.5.8）/ 44px（2.5.5）需落到产物 CSS 规则级断言** | 主题有交互控件且追求无障碍达标 | 纯静态文档主题（仍建议，但非必需） |
| **颜色 token 按用途拆分（背景/实心/文字）以达 WCAG AA** | 主题支持深浅双主题或自定义主色 | 单色、无自定义 |
| **图片 Pipeline + render hook 的分支覆盖依赖夹具** | 主题用 `resources` 处理图片 | 不处理图片 |
| **多 Hugo 版本矩阵真实构建**（而非读文档判断） | 主题声明支持版本范围 | 只支持单一最新版 |
| **文档一致性门禁（README/CHANGELOG/基线不得回退）** | 主题对外发布且文档是交付面 | 内部一次性主题 |
| **CI 结构本身作为被测对象**（防删步骤/加 `if:false`/`continue-on-error`） | 主题用 CI 做门禁且门禁即质量承诺 | 无 CI 的项目 |

## 4. 从"实例"提炼"方法"的示例

| Nebula 实例（C） | 提炼出的通用方法（A） |
| --- | --- |
| `bool-param.html` 返回 `dict` | 模板返回值受类型包装影响；布尔语义必须显式解析 |
| `slice-runes.html` | 字符串长度语义（rune vs byte）必须显式统一 |
| `locale.html` 的 0.158 分支 | 跨版本差异先探测再用；探测禁用 `cond` |
| `author-config.html` 默认关闭 | 可能改变默认产物的新功能，做成默认关闭的可选层 |
| `check_index.py` 的 `_looks_like_build_source` | 配置感知必须绑定"本次构建实际使用的源根" |
| `TAILMARKER_*` 尾部标记 | 用"内容完整性标记"检测截断类假绿 |

| Nebula 实例（C） | **不应该**被提炼成通用规则 |
| --- | --- |
| 具体页面数 `212/291/286` | 任何主题的页面数 |
| 具体 Hugo 版本组合 | 任何主题的版本范围 |
| 具体断言条数 | "必须有多少条断言" |
| `authors.pages` 这一配置键 | 所有主题都必须叫这个名字 |

## 5. 对通用 Skill 的落地要求

1. **A 档**写进 `SKILL.md` 的硬约束区与 `references/`，作为**无条件规则**。
2. **B 档**写进 `references/`，措辞必须是 **"若…则…"**，并注明判断条件。
3. **C 档**只允许出现在**教学案例/反例**中（如 `BUG_FIX_CASEBOOK.md` 的案例），**不得**出现在规则条款里。
4. 任何从 C 提升为 A 的条目，**必须能写出"为什么与具体项目无关"的理由**；写不出就留在 C。
5. 引入新规则前自检：**"换一个完全不同的 Hugo 主题，这条还成立吗？"** 不成立 → 降档。
