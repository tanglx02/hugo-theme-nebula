# OPEN_LIMITATIONS — 未完成项与接受为限制的清单

> 资料性质：用于通用 Hugo 主题开发 Skill 的经验沉淀。
> 事实标注：**【已证实】**＝有代码/CI/报告支撑；**【结论】**＝开发方判断；**【待验证】**＝未经独立第三方确认。
>
> 本文档诚实登记"**没做**"和"**做了但不完美**"的部分。价值在于：
> **一个主题的可信度，取决于它是否敢于把边界说清楚。** 把"未验证"写成"已验证"，是比 bug 更严重的问题。

---

## 0. 三类区分

| 类别 | 含义 | 处理方式 |
| --- | --- | --- |
| ACCEPTED-LIMITATION | 有意不做，且写明原因与用户影响 | 接受，文档提示用户 |
| NOT-VERIFIED | 未验证路径（能力/环境不可控） | 如实登记，**不冒充已验** |
| PLANNED-NOT-DONE | 计划内但本轮明确不做 | 记录，留给后续 |

---

## 1. ACCEPTED-LIMITATION（接受为限制）

**【已证实】** 以下均来自 `docs/final-cleanup-issue-tracker.md` §11.1 与 `docs/稳定基线.md`。

| 项 | 为什么不做 | 用户影响 | 何时值得修 |
| --- | --- | --- | --- |
| **M18 嵌套菜单** | 差距分析评估价值较低，且会显著增加菜单模板复杂度与回归面 | 两级以内菜单可用 | 有明确用户需求且愿意承担回归面时 |
| **第三方 SRI / CSP**（BUG-P3-003 / SEC-02） | 不预置哈希（会随上游版本漂移而失效并误伤用户）、不写死 CSP（需按用户实际启用的服务定制）。默认**全部第三方功能关闭** | 启用第三方服务者需自行配置 `integrity` / CSP；README 已给模板 | 若提供"配置生成器"或按版本自动取哈希的机制时 |
| **正文外链图无尺寸**（BUG-P3-004） | 外链图片尺寸在**构建期不可知** | 有 CLS 风险；README「图片处理」已提示；画廊复用 Pipeline 已尽量补尺寸 | 外链图能提供尺寸元数据，或改用可探测尺寸的来源时 |
| **弹窗无关闭按钮**（OBS-R2-001） | 界面已有 Esc 提示，加按钮会与极简设计冲突；**不构成缺陷** | 非缺陷 | 用户反馈可发现性不足时 |

> **关于 M16 的历史说明【已证实】**：作者档案页曾登记为 ACCEPTED-LIMITATION（怕新增 taxonomy 改变默认 URL 结构），后经重新评估，**该顾虑通过"默认关闭的可选启用"设计完全化解**，已转为**已实现**。此处保留原判定与撤销原因，供追溯。**结论：不是所有"限制"都真的无法解决——有些只是缺少一个向后兼容的设计。**

## 2. NOT-VERIFIED（未验证路径）

**【已证实】** 以下为**诚实登记**，明确**未**做实际验证：

| 项 | 未验证的原因 | 已做的部分 |
| --- | --- | --- |
| **真实第三方服务连通性**（giscus / waline / twikoo / disqus / busuanzi） | 需真实账号，非主题能力范围 | 只验**渲染**与**关闭态零第三方请求** |
| **真实屏幕阅读器**（NVDA / VoiceOver） | 需真实环境与人工 | 只做**属性与焦点级**验证（`role/aria-modal`、focus trap、焦点恢复） |
| **`hugo server` 实时预览（livereload）** | 长时预览会话未做 | 只验生产产物**不含** livereload |
| **超大规模站点（>2000 篇）** | 未做更大规模压测 | 压测数据到 **2000 篇**已验证索引与搜索 |
| **JS 禁用下的搜索降级** | 未逐条人工确认 | 有 `no-JS` 相关断言，但降级体验未逐步确认 |

**【结论】** 这些不是"做不到"，而是"需要外部条件或人工"。**它们的正确处理方式是登记为未验证，而不是用间接证据声称已验。**

## 4. 独立第三方验收的真实覆盖范围（**重要，勿混淆**）

**【已证实】** 必须把"**某个 SHA 上的专项验证**"与"**整个新候选的完整验收**"严格区分：

| 事实 | 状态 |
| --- | --- |
| 独立第三方验收（结论 PASS WITH LIMITATIONS）针对的候选 SHA | **`f3549a5dacb503bc4cdf99556a5d04b51e753911`**（历史候选） |
| 该轮验收中，**M16 作者档案页**接受了独立第三方的**专项验证** | **是**（`f3549a5`） |
| 该轮遗留项以 R2 / R3 系列收尾 | 是（详见 `docs/final-cleanup-issue-tracker.md` §12） |
| **当前最新候选的整个提交 SHA**（主题代码基线 `8363d4b`，及其后的文档提交 `e03a6c8`）是否重新执行过**完整独立第三方验收** | **否** |
| M16 相关实现文件在 `f3549a5..8363d4b` 之间是否变动 | **否**（`git diff --name-only f3549a5 8363d4b` 对其为**空**） |

**【结论·待验证】** 由此得到两条**不得越界**的表述：

1. **可以**说：M16 的实现文件自 `f3549a5` 起未再改动，因此 `f3549a5` 上对 M16 的专项验证结论**对当前文件仍然相关**（是"文件未变"的推论，不是"重新验证过"）。
2. **不得**说：当前候选（`8363d4b` / `e03a6c8`）整个已被独立第三方验收。
   `f3549a5` **之后**仍有改动，例如 `4a4ea01` 修改了 `layouts/partials/head.html`（空标题修复）、
   `.github/workflows/ci.yml` 与多个 `tools/*`，`8363d4b` 修改了 `tools/check_index.py`。
   **`head.html` 同时承载作者 meta / JSON-LD 输出**，故"M16 专属文件未变"并不能推出"M16 的全部输出路径未变"。

**【结论】** 其余仍待独立验证的路径（与上文 §2 一致，均为开发方自测）：

- 本轮**新增门禁**（`check_home_layouts` / `check_reading_experience` / `check_new_features` / `check_author_pages`）的**故障注入自证**均为开发方执行。
- 本轮修复的**假绿**（`check_index` contentLimit）与**假红**（`verify_search_shard`）由开发方自测暴露并修复。
- 真实第三方服务连通性、真实屏幕阅读器、`hugo server` 长时预览、>2000 篇规模（见 §2）。

> 注：上述结论在候选上已取得**完整 CI 证据**（`8363d4b`：PR `38171213190` + dispatch `38171253788` 14/14；
> `e03a6c8`：PR `38188954023` + dispatch `38189345376` 14/14），
> 但 **CI 通过 ≠ 独立第三方验收**；两者是不同层级、不同 SHA 上取得的证据，不可互相替代。

## 5. 边界与"什么情况会被判定为未完成"

以下情形**必须判失败**，不得降级为 PASS（来自 `docs/测试说明.md` 与基线）：

- Release 全站审计达到 `AUDIT_PAGINATION_LIMIT` → 意味"可能有未发现的分页页" → 判**未完成**。
- 任何门禁"零用例执行" → 判失败。
- inventory 缺失或与本次构建指纹不符 → 硬失败。
- 主索引失败被伪装成"没有结果" → 判失败。

## 6. 迁移到通用主题 Skill 的建议

| 可固化为规则 | 不写进通用 Skill（项目专有） |
| --- | --- |
| 三类区分（接受限制 / 未验证 / 计划内未做） | 具体功能名（M18 等） |
| "接受限制必须写明原因与用户影响" | 具体第三方服务清单 |
| "未验证不得冒充已验" | 具体篇数阈值（2000） |
| "开发方自测 ≠ 独立验收" | 具体门禁数量 |
| "达上限即判未完成" | 具体 `AUDIT_PAGINATION_LIMIT` 值 |
| "限制有时可通过向后兼容设计化解" | M16 的具体设计 |

**【结论】** 通用 Skill 应要求"**任何主题都必须维护一份 OPEN_LIMITATIONS**"，并要求每条限制写明：**影响、适用性、变通方法、何时值得修**。这比"假装完美"更能建立信任。
