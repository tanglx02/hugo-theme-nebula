## 二、P1：分页发现的队列耗尽式改造

### 问题

v1.0.5 的 `discover_pagination()` 使用 `max_urls=800` + `rounds=3`：

```python
for _ in range(rounds):        # 固定 3 轮
    ...
    if not worklist or len(found) >= max_urls:
        break                  # 达到上限也只是 break，随后照常判 PASS
```

当前 125 页的站点能通过，但**逻辑上无法证明"所有分页都被发现"**：第 4 层及更深的分页
永远不会被发现；达到 800 上限后仍会输出"覆盖完整"。

### 改造

- BFS 直到**队列耗尽**（没有任何新分页页）才算完成，`rounds` 降级为纯记录；
- 安全上限保留为 `AUDIT_PAGINATION_LIMIT`（默认 10000），但语义变为"防失控"：
  **达到上限即判定"未完成全站发现"并 FAIL**，不允许继续判 PASS；
- 输出 `SITEMAP / DISCOVERED / ROUNDS / LIMIT / EXHAUSTED` 全套统计；
- 三条硬断言：审计的 sitemap 页数 == sitemap HTML 页数；分页爬取已耗尽；8 类必需页面齐全。

### 规模自测（`tools/check_pagination.py`，19/19 通过）

对**真实 Hugo 构建产物**（非 mock）逐一验证：

| 场景 | 结果 |
| --- | --- |
| 1 个分页 | 发现 1 个，与产物真值完全一致 |
| 3 个分页 + 分类/标签/多 section 分页 | 发现 17 个，与真值完全一致（含 `/categories/big/page/2..7/`、`/tags/hot/page/2..6/`、`/tutorials/page/2..3/`、`/notes/page/2/`） |
| 10 个分页 | 发现 10 个，末页 `/posts/page/11/` |
| 100 个分页 | 发现 100 个，末页 `/posts/page/101/`，rounds=27 |
| 达到 limit=50 | 停止发现，`exhausted=False`，`limit_reached=True` → 判未完成 |

> 一个容易算错的点：Hugo 的分类/标签 term 会**跨 section 聚合**（posts + tutorials + notes
> 中带同名分类的文章都计入同一个 term 页），真值期望必须按聚合后的总数计算，否则会把
> 正确的爬取结果误判为"多余"。

## 三、P2：评论系统 i18n

### 修复

`comments.html` 中 giscus / Waline / Twikoo 的语言参数原本硬编码 `zh-CN`。现按 Hugo
语言映射，并支持 per-provider 显式覆盖：

| 站点语言 | 组件 locale |
| --- | --- |
| `zh` / `zh-cn` / `zh-hans` | `zh-CN` |
| `zh-tw` / `zh-hant` / `zh-hk` | `zh-TW` |
| `en` / `en-us` / `en-gb` | `en` |
| 未命中映射 | 原样传递（不强造第三方不存在的 locale） |

覆盖方式：`params.comments.giscus.lang` / `.waline.lang` / `.twikoo.lang`。

### 验证（`tools/check_comments.py`，12/12 通过）

- 评论关闭时：全站 HTML **零**第三方 URL（giscus.app / unpkg.com / jsdelivr / disqus.com）
- giscus：zh 页 `data-lang="zh-CN"`、en 页 `data-lang="en"`
- Waline / Twikoo：`lang` 跟随站点语言，`serverURL` / `envId` 正确
- Disqus：脚本 src 使用配置的 shortname（Disqus 无 locale 参数）
- `giscus.lang = 'en'` 时 zh 站也输出 `data-lang="en"`（覆盖生效）
- 静态检查：映射表之外无硬编码 locale

## 四、P2：真实多语言站点回归

`tools/multilingual.toml` 对 exampleSite 做**真实 Hugo multilingual 构建**（非 locale 替换）：
zh-CN 在根路径（URL 与单语言版一致），en 在 `/en/` 子路径，使用独立 `contentDir`。

`tools/verify_multilingual.py` **23/23 通过**：

| 验证项 | 结果 |
| --- | --- |
| URL 结构 | zh `/posts/...`、en `/en/posts/...` |
| 同一篇文章两个语言版本 | 中文 / 英文标题均正确 |
| `<html lang>` | zh-CN / en |
| hreflang | 双向输出，href 指向对方语言版本 |
| canonical | 各语言指向自身 URL |
| og:locale | `zh_CN` / `en_US` + `og:locale:alternate` |
| RSS | `/index.xml` 与 `/en/index.xml` 均存在，en channel 指向 `/en/` |
| sitemap | 根为 sitemapindex，列出 `/zh-cn/` 与 `/en/` 子 sitemap |
| 分类 / 标签 | `/en/categories/environment/` 存在，zh 侧无此 term（按语言隔离） |
| 搜索 | `/en/index.json` 含英文内容，zh 索引不含（不串语言） |
| Series | 两语言各自渲染，互不合并 |
| UI 文案 | 复用 `verify_i18n.py` 对 `/en/` 全量断言（26 项） |

> 踩坑记录：`.en.md` 后缀在**单语言**构建下会被当作普通页面渲染出 `/posts/xx.en/`，
> 污染单语言产物。必须用 per-language `contentDir`。

## 六、门禁可信度：五次故意故障注入

每一次都验证了 **exit 1 与 CI 真实变红**，而不是靠改测试制造"看起来通过"。

| 注入 | 预期失败门禁 | 实际结果 | Run |
| --- | --- | --- | --- |
| A：分页上限压到 1 | Release full-site audit | 三浏览器全部在 "Full-site audit" 失败，报 `LIMIT REACHED` | `37753707374` |
| B：漏掉 `/page/3/` | Release full-site audit | 三浏览器全部失败，报"全站审计缺少必需页面类型：分页 /page/3/" | `37753707374` |
| C：评论写死 `zh-CN` | static-checks / Comments | Comments 步骤失败（3 条断言） | `37753033988` |
| D：重复 `id` | static-checks / HTML quality | HTML quality 失败，`dup-id x129` | `37752376410` |
| E：内容图缺 `alt` | static-checks / HTML quality | HTML quality 失败，`img-alt x16` | `37752376410` |

> 经验：GitHub Actions 中某个 step 失败后**后续 step 会被跳过**。D/E 命中了同一步骤，
> 而 C 命中的是靠后的 Comments 步骤，因此必须分批推送才能各自取证。
>
> 另一个修正：D 最初写成"同一元素写两个 `id` 属性"，结果查不出来 —— HTML5 会忽略重复属性。
> 改为**两个元素共用同一 id** 后立即被抓出（129 处）。

### 首次 tag CI 的失败与修复

```
320px /posts/ :: 4 张图片未完成: soc.svg / container.svg / ssh.svg / ...
320px /       :: 1 张图片未完成: hugo.svg
```

全是 SVG 封面图，本地 webkit 126 页 × 4 视口 0 问题。人为注入 3s 网络延迟后复现：
需要约 12s 才收敛。**单次 8s 预算 + 单次 8s 复查在 CI 高负载下偶发不够。**

修复：复查预算逐轮加倍（8s → 16s → 32s），`REVIEW_ROUNDS=2`。判定标准不变 ——
所有轮次结束后仍未完成的图片照样判为缺陷。

双向验证：

| 场景 | 期望 | 实测 |
| --- | --- | --- |
| 慢速 3s 延迟 | 收敛为 0，不误报 | `settle=0`，12.6s |
| 注入真实挂起图片（端点永不响应） | 仍判缺陷 | `settle=1`（耗时 65s，属预期代价） |
