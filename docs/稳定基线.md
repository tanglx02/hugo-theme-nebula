GitHub 已宣布 `ubuntu-latest` 将于 2026-10-19 起迁移到 Ubuntu 26.04。

## 2. CI 结构（数量由工具计算，不手写）

生产门禁 = `.github/workflows/ci.yml`。job 数量**不是**文档里的数字，而是
`tools/check_ci_jobs.py` 按 GitHub matrix 展开规则（`include` 合并 / `exclude` 剔除）
算出来的，并与 workflow 注释里登记的清单比对：

```
# CI-JOBS: build=6
# CI-JOBS: subdir=1
# CI-JOBS: static-checks=1
# CI-JOBS: browser-tests=3
# CI-JOBS: release-full-audit=3
# CI-JOBS-TOTAL: 14
# CI-JOBS-PUSH-TOTAL: 11       （非 tag 推送：Release job 被 if 跳过）
```

| Job | matrix 维度 | 展开数量 | 备注 |
| --- | --- | --- | --- |
| build | `hugo-version` ×6 | 6 | 上传 `public-zh-cn` 产物 |
| subdir | — | 1 | `/blog/` baseURL |
| static-checks | — | 1 | 全部静态门禁 |
| browser-tests | `browser` ×3 | 3 | `audit.py` **抽样**视口：chromium 7（320/375/390/430/768/1024/1440）、firefox 3、webkit 3（375/768/1440） |
| release-full-audit | `browser` ×3 | 3 | 仅 tag `v*` 或手动触发 |

- **tag 推送：14 个 job**（含 3 个 Release）
- **普通 push / PR：11 个 job**（Release job 被 `if` 跳过）
- 改动 matrix 必须同步改注释，否则 `check_ci_jobs.py` 判失败 —— 这是 v1.0.8
  之前一直把 12 写成 13 的根因，现在由工具兜住。

> 注：Hugo 矩阵自第二轮修复起由 5 个版本（0.128/0.162/0.166/0.167/latest）
> 扩为 **6 个**（新增 0.148.0），以覆盖复验报告要求的全部版本边界。

### 权限

- 顶层 `permissions: contents: read`
- 任何 job **不允许** `*: write`（由 `check_workflow_policy.py` 断言）
- `subdir` 这类只需要检出源码的 job 进一步设 `permissions: {}`
- checkout / cache / artifact 依靠 Actions 运行时凭证，不需要给 `GITHUB_TOKEN` 写权限

## 4. Release 全站审计：三条独立证据链

| # | 证据 | 工具 | 说明 |
| --- | --- | --- | --- |
| 1 | 构建产物 inventory | `html_inventory.py` + `audit.py` | `public/**/*.html` 全部被浏览器加载审计，硬断言 `EXPECTED == AUDITED` |
| 2 | pagination crawler | `audit.py` 的 `discover_pagination` | 交叉验证：所有可爬取分页页都能从列表页走到 |
| 3 | alias 静态结构 | `check_alias_pages.py` | 浏览器打开 alias 会被重定向到 canonical，观察到的是**目标页**，因此 alias 必须单独静态验证 |

Release 报告里必须出现的数字（示例站点实测）：

```
PUBLIC HTML FILES = 212
FILESYSTEM EXPECTED URLS = 212
SITEMAP HTML URLS = 122          # sitemap 是 SEO 索引，不是真值
PAGINATION CROSS-CHECK: 真值 N（另有 M 个别名分页页不被链接，由 inventory 覆盖）
DISCOVERED PAGINATION URLS = N
PAGINATION MISSING = 0
PAGINATION UNEXPECTED = 0

MISSING URLS = 0
UNEXPECTED URLS = 0
DISCOVERY FAILURES = 0
PAGINATION EXHAUSTED = YES
```

## 5. 契约清单

### 5.1 搜索契约

- 索引字段：`date`（机器格式 `YYYY-MM-DD`）、`dateDisplay`（**构建期** i18n 结果）
- **前端只负责原样输出 `dateDisplay`**：不得在 JS 里猜语言，也不得再格式化一次
  （`check_date_format.py` 会拒绝 `toLocaleDateString` / `Intl.DateTimeFormat`）
- 缺日期的文章：`date` 与 `dateDisplay` 均为空串，UI 省略日期片段，绝不显示 `0001-01-01`
- 索引结构向后兼容：旧字段（title/url/date/summary/content/key/tags/categories/series）一个不少
- 三种模式保留：`auto` / `single` / `shard`，`chunk` 按体积分块；本轮不做倒排索引
- 竞态：先 await 索引再渲染，用 token 丢弃过期渲染；索引未就绪显示加载态，不误报"无结果"
- 失败：主索引失败明确报错 + 重试；分片部分失败提示"结果可能不完整"，不伪装成"没有找到"
- 高亮：`esc` 之后再做正则替换；`<mark>` 不嵌套；文本不丢失；查询串不能产生 XSS

### 5.2 分页与 URL 分类契约

- **文章页** = `/<content-section>/<slug>/`，section 取自 `params.content.sections`
  （回退 `params.content.section`，再回退 `posts/tutorials/notes/projects`）
- `/categories/<term>/`、`/tags/<term>/`、`/archives/`、`/page/N/`、**都不是**文章页
  （旧实现 `/[^/]+/[^/]+/` 会把 term 页误判成文章页并从 crawl 种子里剔除）
- `pagination.path` **可配置**（Hugo `[pagination] path`）：crawler 优先从构建产物反推 token，
  再读配置，最后才用默认 `page`；不允许写死 `page`
- crawl 种子 = 非文章页 且 非 alias 且 **非分页页**（分页页是 BFS 产物，进 visited 会让交叉验证退化）
- `exhausted` = 队列耗尽 **且** 零失败 **且** 未达安全上限

### 5.3 Modal 无障碍契约

`createModalA11y`（`assets/js/main.js`）为搜索弹窗与灯箱提供同一套行为：
焦点移入 → Tab/Shift+Tab 循环 → 背景 `inert` + `aria-hidden` → Escape 关闭 →
关闭后焦点归还触发元素（深链无触发元素时退化为 dialog 自身）→ 快速开关幂等。

**页面滚动锁定也必须由工厂统一管理（BUG-P1-001 的教训）**：
- 所有 modal 共用一份 **引用计数**滚动锁；关闭路径（遮罩 / Escape / 关闭按钮 /
  深链 / 快速开关）不可能绕过它；
- 恢复的是**打开前真实的 `body.style.overflow`**，不是无条件置空；
- 两个 modal 同时打开时，关闭其中一个**不会**解除另一个仍持有的锁；
- 由 `tools/verify_modal_scroll.py` 在 Chromium / Firefox / WebKit 三引擎逐条验证。
- 判定"能否滚动"必须用**真实用户输入**（滚轮 / PageDown）：`overflow: hidden`
  仍然允许 `window.scrollTo` 程序化滚动，用 scrollTo 判定会得到假结论。

### 5.4 i18n 契约

- UI 文案一律来自 `i18n/*.yaml`，模板不得写死中文/英文（`check_i18n_hardcode.py`）
- UI 日期一律 `i18n "common.dateFormat"`；机器格式（RSS / JSON-LD / `<time datetime>` /
  搜索索引 `date`）需白名单或 `machine-format:` 行内标注
- 语言切换配置必须**复制到站点目录内**再用相对路径 `--config` 引用：
  Hugo 会静默忽略找不到的配置文件，表现为"英文构建实际仍是中文"

### 5.5 图片与复制契约

- 图片：`loading="lazy"` + 尺寸占位；审计会滚动触发并等待懒加载完成，预算分级 8/16/32/64s
- 判定时只统计"真的会发起请求"的图片（有 src 且有布局尺寸），灯箱占位图不参与
- 复制：只有成功/失败两种结果，**不允许超时算成功**（`verify_copy.py` 逐条路径验证）

### 5.6 安全契约

- 构建产物与主题源码不得出现 `javascript:` / `vbscript:` / 空 `href` / inline handler
- 外链 `target="_blank"` 必须带 `rel="noopener"`
- `role="dialog"` 必须带 `aria-modal="true"` 与可访问名称
- workflow 不允许任何 write 权限（`check_workflow_policy.py`）
- `util/rel-url.html` 必须**在源头**拒绝 `javascript:` / `vbscript:` / `data:`(非 image)
  —— 调用方普遍 `| safeURL`，等于信任它的返回值（SEC-03）
- 搜索结果链接必须过 scheme 白名单（只放行同源相对路径与 http(s)），
  非法项渲染为不可点击文本（SEC-01）
- 第三方脚本使用 `https://` 绝对地址（不用协议相对 `//host/…`）；
  SRI 由用户通过 `params.*.integrity` 提供，主题不预置哈希

### 5.7 内容健壮性契约（极端输入不得中断整站构建）

- **不允许出现越界的 `slicestr`**：`slicestr` 按 **rune** 计数，长度不足会 panic
  并终止整站构建；`len` 返回**字节数**，不能用来判 rune 长度（"中" 的 len=3）。
  统一走 `partial "util/slice-runes.html" (dict "text" … "n" …)`（BUG-P1-003）
- 空 / 单字符 / 单 CJK / 单 emoji / 纯空白标题、空站点标题、无头像且 author 为空、
  空正文、非 ASCII slug、BOM front matter，**都必须能成功构建**（`gen_testdata.py` 固化为夹具）
- 未配置 `taxonomies` 的站点也必须能构建（`site.Taxonomies.*` 需 `default dict` 兜底）
- 缺 `date` 的文章：页面侧显示本地化"未标注日期"或省略，JSON-LD **不输出**日期字段，
  绝不出现 `0001-01-01`（由 `check_html_quality.py` 的 `zero-date` 规则拦住）
- 空正文不显示"0 分钟 / 0 字"

### 5.8 颜色与对比度契约（BUG-P2-003）

颜色 token 按用途分工，不得混用：

| token | 用途 | 约束 |
| --- | --- | --- |
| `--brand` / `--accent` | 背景 / 边框 / 装饰 | 可保持鲜亮 |
| `--brand-solid` | **承载白字的实心背景** | `#fff` 文字对比度 ≥ 4.5:1 |
| `--brand-ink` / `--accent-ink` | **文字** | 对比度 ≥ 4.5:1（大号文字 ≥ 3:1） |
| `--text-muted` | 次要文字 | 对 `--bg-elev` / `--bg-soft` / `--bg` 均 ≥ 4.5:1 |

浅色与深色两套主题都必须达标；由 `tools/verify_contrast.py` 在真实浏览器里
取 computed style（含 alpha 合成）逐元素计算，并要求受检选择器**不得空转**。
> 度量前必须禁用 CSS 过渡：主题带 `transition: all .2s`，切换主题后立刻取色
> 会读到过渡中间值（实测会把 dark 的 5.19:1 读成 1.1:1 的假故障）。

### 5.9 响应式断点契约（BUG-P2-002）

- **头部导航断点 = 900px**，有意高于内容断点 768px：英文/其它语言导航文案更长，
  769–869px 视口下 `nav`(433px) + `header-actions`(217px) 会撑破布局
- ≤900px：隐藏行内导航、显示汉堡、搜索按钮收成图标；>900px：反之
- 由 `tools/check_responsive_overflow.py` 在边界宽度（769/800/869/900/901）
  对中文站与英文站同时验证"无整页横向溢出 + 断点行为正确"
- 触控目标：≤900px 时图标按钮与主按钮提升到 44×44（WCAG 2.5.5 AAA 目标）

### 5.10 版本能力探测契约

跨版本差异的 API 一律**先探测再用**，并在旧版本上给出明确行为：

| 能力 | 引入版本 | 低版本行为 |
| --- | --- | --- |
| `resources.Publish` | 0.166.0 | auto 回退单文件（WARN）；显式 shard 报错 |
| `.Language.Locale` | 0.158.0 | 回退 `.Language.LanguageCode`，走 `util/locale.html` |
| `reflect.IsImageResourceProcessable` | 0.128 无 | 不用它；改用 MediaType 白名单 |

探测方式：`hugo.Version` 解析 major/minor（`split` + `int`），**不要**用 `cond`
——Go 模板的 `cond` 会先求值两个分支，会触发旧版本上不存在的字段访问错误。

### 5.11 作者档案页契约（M16，可选启用）

**默认零改变是硬契约**：`params.authors.pages` 缺省为 `false`，且站点**不注册 `authors` taxonomy** 时，
主题**不输出任何作者档案结构**，所有站点 URL 与页面数**不变**（门禁 BC1：与「无本功能」基线主题
`37c3da6` 在**规范化**〔打包 CSS 文件名哈希 / SRI / RSS `lastBuildDate`〕后**逐字节一致**，
非"原始字节完全一致"）。

> 口径澄清：**只有不注册 `authors` taxonomy 才真正减少页面数**（exampleSite 启用→291，不注册→286，
> 差异恰为 5 个 `/authors/` 页）；仅把 `params.authors.pages=false` 而 taxonomy 仍注册时，
> Hugo 依旧生成 `/authors/`，产物仍为 291。

| 契约 | 内容 |
| --- | --- |
| 单点配置 | `util/author-config.html` 是唯一配置入口，返回 `{enabled, taxonomy, profiles}` |
| 启用条件 | 注册 `authors` taxonomy **且** `params.authors.pages=true`；taxonomy 未真正注册时降级 `enabled=false`（防死链） |
| URL | 默认无 `/authors/...`；启用后 `/authors/`（索引，复用 `list.html`）+ `/authors/<term>/`（档案页，`term.html`） |
| 单数/复数 | 仅复数列表 `authors: [...]` 建立 term；单数 `author:` 只作署名回退，**不建 term**（Hugo 既有机制） |
| CJK/特殊字符 | **禁用 `urlize` 拼路径**（对 CJK 返回 percent-encoded，`GetPage` 返回 NONE）；改用遍历 `site.Taxonomies` 按 `Page.Title` 大小写不敏感匹配 |
| 资料卡 | 字段全可选；`avatar` 走 `util/avatar-url.html` 校验；`url`/`links` 仅 `http(s)`；无资料不输出空卡片 |
| 跨版本 | 0.128.0 / 0.148.0 / 0.162.0 / 0.166.0 / 0.167.0 五版本一致（exampleSite `HTML=291`、作者 term **2**、`author-link` **56**；合成探针站文章页 `author-link=2`） |

## 7. 迭代流程（v1.0.9 之后）

v1.0.9 是长期稳定基线。**不再创建 v1.1.0 之前的"验收版本"循环**，以后新增功能按：

```
开发 → 单元/专项测试（tools/ 下新增或扩展，失败即 exit 1）→ CI → Release
```

三条硬性要求：

1. 新增功能必须通过现有 CI，不得为了让它过而放宽判定；
2. 改动 matrix / 权限 / runner / action 版本，必须同步 `check_ci_jobs.py` 与
   `check_workflow_policy.py` 的登记；
3. 任何"结构性判定"（文章页、分页、alias、日期）都不得写死站点配置，必须可配置或可推断。
