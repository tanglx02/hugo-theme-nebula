## 2. 本轮修复的问题

编号规则：`P0-x` 阻断级、`F-x` 功能缺陷、`T-x` 测试体系缺陷。
每项都给出**复现方法 → 根因 → 修改 → 修复后验证**，并标注验证等级。

---

### T-1【P0】5 个测试脚本「打印 FAIL 却 exit 0」——CI 假绿灯的根因

- **复现方法**：`grep -c "sys.exit" tools/*.py` → `audit.py`、`interactions.py`、
  `verify_search_edge.py`、`verify_baseurl.py`、`link_check.py` 均为 **0**；
  人为注入缺陷后运行脚本，输出 `FAILED: ...` 但 `echo $?` = 0。
- **根因**：脚本只在最后由 `print` 输出失败统计，从未把失败状态转成进程退出码。
  CI 依据退出码判定，因此这些步骤**永远不会失败**。
- **修改**：
  - 新增 `tools/_testlib.py`：`Harness` 统一收集结果，`finish()` 为唯一出口，
    失败即 `sys.exit(1)`；输出机器可读 `TEST-RESULT: {...}` 行。
  - 五类情况全部判失败：断言失败、脚本异常、依赖缺失（`require_playwright`）、
    浏览器启动失败、站点/服务器不可达、**零用例执行**（防止空跑算通过）。
  - 上述 5 个脚本全部改造接入。
- **修复后验证**：
  - 本地：故意让每个脚本失败 → `exit=1`（见第 6 节三次注入的本地预验证）。
  - CI：注入缺陷后对应 job 真实变红（run ID 见第 6 节）。
- **验证等级**：本地测试 ✅ / CI 测试 ✅

### T-2【P0】`audit.py` 关键前置失败被静默吞掉

- **复现方法**：把 `BASE` 指向不存在的端口 → 旧版打印 `sitemap error` 后继续，
  用 8 条硬编码 URL 得出「无问题」；浏览器启动失败也只 `print` 后 `continue`。
- **根因**：`get_urls()` 的 `except` 分支只 `print`；浏览器 `launch` 异常被 `continue`。
- **修改**：sitemap 获取失败 / 页面数 < 5 / 未选择任何浏览器 / 浏览器启动失败 /
  站点不可达 → 全部走 `fatal_error()`，最终 `exit 1`。
- **修复后验证**：本地把服务停掉后运行 → `[FATAL] 被审计站点不可达` 且 `exit=1`。
- **验证等级**：本地测试 ✅

### T-3【P0】CI 覆盖度不足：Release 阶段无全站扫描

- **复现方法**：PR 阶段审计只抽样 `posts[:8] + 其他 12`（共 23 页）；
  实际站点有 45 个可审计页面。
- **根因**：为避免每次 PR 过慢，审计只做抽样，但**没有任何阶段做全站扫描**。
- **修改**：`audit.py` 新增 `AUDIT_FULL=1`（扫描 sitemap 全部页面）；
  CI 新增 `Release full-site audit` job，仅 tag（`v*`）或手动触发。
- **修复后验证**：该 job 立刻抓到 2 个真实缺陷（见 F-2、F-3），修复后 tag CI 全绿。
- **验证等级**：CI 测试 ✅
- **附带价值**：这是本轮最有价值的一处覆盖度提升——**抽样通过的页面并不能代表全站**。

### T-4【P0】`i18n` 占位符 Bug：页面上直接显示 `{posts}`

- **复现方法**：`hugo` 构建后 `grep -o "共 {posts} 篇文章" public/archives/index.html`。
- **根因**：Hugo 的 `i18n` 只解析 **Go 模板语法**（`{{ .n }}`），
  而 `i18n/*.yaml` 里用的是自定义 `{n}`（这套写法是给前端 `tf()` 用的）。
  模板侧调用 `i18n "list.count" (dict "n" ...)` 时占位符**不会被替换**。
- **修改**：区分两类键——
  - 模板消费的键改为 Go 语法：`common.minutes`、`post.readingTime`、`post.wordCount`、
    `series.partOf`、`archive.count`、`list.count`、`list.taxonomyCount`、`list.termsCount`；
  - JS 消费的键（`search.resultCount` / `partialFailed` / `partialNoResult`）保留 `{n}`。
- **修复后验证**：`verify_i18n.py` 断言「无未渲染的 Go 模板占位符」，
  三语言 26/26 通过；归档页显示「共 29 篇文章 · 1 个年份」。
- **验证等级**：本地测试 ✅ / CI 测试 ✅

### F-1【功能】搜索分片失败被误报为「没有找到」

- **复现方法**：在分片站点上让某个 chunk 返回 404，搜索该 chunk 内的正文关键词。
- **根因**：`hits.length === 0` 时无条件渲染 `noResultPrefix/noResultSuffix`，
  与 `SHARD_FAILED` 状态无关 → 用户会以为内容不存在。
- **修改**：新增 `search.partialNoResult` 词条；索引不全时显示
  「部分搜索索引加载失败（N 篇未能加载），因此暂未找到结果……请重试」。
- **修复后验证**：`verify_search_shard.py` 14/14（含 4 项深层关键词语义断言）。
- **验证等级**：本地测试 ✅ / CI 测试 ✅

### F-2【功能】page bundle 图片在窄屏被纵向拉伸（真实缺陷）

- **复现方法**：`AUDIT_FULL=1` 扫描 `/posts/zz-images-bundle/`：
  `natural=375x210 render=297x900`（比例 1.79 vs 0.33）。
  抽样审计（23 页）**未能发现**，全站扫描（45 页）才发现。
- **根因**：`render-image.html` 为防 CLS 输出了 `<img width="1600" height="900">`；
  HTML 的 `width/height` 属性会作为 **presentational hint**（`height: 900px`）生效，
  而全局样式只有 `max-width: 100%`，没有 `height: auto`。
  窄屏下宽度被压到 297px、高度仍为 900px → 图片变形。
- **修改**：`img { max-width: 100%; height: auto; border-radius: ... }`，
  保留 `width/height` 属性（防 CLS）同时让高度按比例缩放。
- **修复后验证**：本地 exampleSite 全站审计（45 页 × 375/1440）**0 问题**；
  抽样审计（23 页 × 7 视口）**0 问题**。
- **影响面**：所有使用 page bundle 图片的站点，属用户可见缺陷。
- **验证等级**：本地测试 ✅ / CI 测试 ✅（tag CI 全绿）

### F-3【功能】21px 触屏点击区（真实缺陷）

- **复现方法**：CI 首轮严格审计（退出码生效后）在 exampleSite 320/375/390px 报
  `small-tap-target`：post-card 标题链接 `w=152 h=21`。
- **根因**：`.post-title` 是 `-webkit-box` 容器，其内部无 class 的 `<a>` 实测高度 21px
  （< 24px），不满足 WCAG 2.5.8 触屏目标尺寸。
- **修改**：`.post-title a { display: block; min-height: 24px; padding: 2px 0; }`。
- **修复后验证**：同一审计在 320/375/390 全部 0 问题；修复前 CI run `37694267596`
  三个浏览器 job 的 Audit 步骤全部失败，修复后 run `37695587136` 全绿。
- **验证等级**：CI 测试 ✅

### F-4【功能】`i18n` 语言切换失效（Hugo ≥ 0.158 的 `locale`）

- **复现方法**：用 `defaultContentLanguage = "en"` 覆盖配置构建，`site.Language.Lang` 为 `en`，
  但 `i18n "nav.search"` 仍返回中文。
- **根因**：Hugo ≥ 0.158 起用 **`locale`**（而非已废弃的 `languageCode`）决定翻译包；
  站点 `hugo.toml` 里的 `locale = 'zh-CN'` 未被覆盖。
- **修改**：测试/CI 的语言覆盖配置显式设置 `locale`（`tools/lang-en.toml`、`tools/lang-zh-TW.toml`）；
  README 的多语言示例同步说明。
- **修复后验证**：英文构建输出 `Latest posts` / `Search` / `May 4, 2026` / `Anchor link`。
- **验证等级**：本地测试 ✅ / CI 测试 ✅

## 4. 架构调整

1. **测试层与产品层解耦**：所有测试断言集中在 `tools/`，通过 `_testlib.py` 统一退出码语义；
   产品代码不感知测试。
2. **审计的页面范围可配置**：PR 抽样 / Release 全量，通过 `AUDIT_FULL` 控制，避免拖慢 PR。
3. **i18n 边界清晰化**：模板侧用 Go 模板占位符，JS 侧用 `{n}` + `tf()`，
   并在 `verify_i18n.py` 中断言「不存在未渲染的 Go 占位符」，防止两类混用再次发生。
4. **测试夹具显式化**：故意制造的缺陷（缺失图片）走显式白名单并打印，
   保证「豁免可见」，不会退化成静默忽略。
5. **输出目录策略**：所有构建/压测/serve 使用**运行期唯一目录**，不做递归删除
   （既规避批量删除保护，也避免误删仓库文件）。

## 8. 性能测试结果（自动化验证 · 本地压测）

命令：`python tools/bench_index.py 500,1000,2000`（每篇约 3000 字，Chromium 单页测量）

| 文章数 | 模式 | 构建(s) | 主索引 | chunk 体积 | chunk 数 | 请求数 | 传输量 | 页面加载 | 索引加载 | 搜索等待 | JS 堆 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 500 | single | 4.2 | 4.4 MB | – | 0 | 1 | 4.4 MB | 126 ms | 532 ms | 647 ms | 6.1 MB |
| 500 | auto→shard | 11.7 | 84 KB | 4.3 MB | 22 | 23 | 4.4 MB | 109 ms | 163 ms | **248 ms** | 5.9 MB |
| 1000 | single | 6.2 | 8.8 MB | – | 0 | 1 | 8.8 MB | 127 ms | 1283 ms | 1322 ms | 8.6 MB |
| 1000 | auto→shard | 5.9 | 168 KB | 8.6 MB | 44 | 45 | 8.8 MB | 103 ms | 331 ms | **379 ms** | 8.8 MB |
| 2000 | single | 18.9 | 17.6 MB | – | 0 | 1 | 17.6 MB | 238 ms | 3988 ms | 3989 ms | 23.5 MB |
| 2000 | auto→shard | 19.3 | 338 KB | 17.3 MB | 87 | 88 | 17.6 MB | 173 ms | 1344 ms | **1347 ms** | 25.7 MB |

结论（自动化验证）：

1. **1000 篇以上 single 模式明显恶化**：2000 篇时索引加载 3.99 s、搜索等待 3.99 s，可用性已崩坏；
   分块模式把等待压到 1.35 s（约 1/3）。
2. **瓶颈是总字节数，不是请求数**：两种模式传输量几乎相同（17.6 MB）；
   分块模式只是让首字节更早、并发更友好。
3. **CPU 不是瓶颈**：CDP `ScriptDuration` 增量仅 1–2 ms，耗时集中在网络与 JSON 解析。
4. **内存**：2000 篇时 JS 堆 23.5–25.7 MB（两种模式接近，因为正文最终都要进内存）。

### 下一版搜索规模化方案（第 14 节展开）

- 渐进渲染：先加载第 1 个 chunk 就出结果，其余后台补齐；
- 构建期生成「词 → chunk」倒排索引（CJK 用 bigram），只拉取可能命中的 chunk；
- 开启服务器 gzip/brotli（静态 JSON 压缩比通常 5–8×）。

## 12. 已知限制与未验证项目

### 已明确记录的限制（不是缺陷，是设计边界）

1. **数学公式不渲染**：未内置 KaTeX / MathJax（按"不引入不必要依赖"取舍）。
2. **正文内联链接点击区 < 24px**：属 WCAG 1.4.10 内联豁免，放大 padding 会破坏排版。
3. **`hugo server` 不能用于产物测试**：会注入 livereload，必须 clean build。
4. **分片索引需要 Hugo ≥ 0.167**（`resources.FromString` + `resources.Publish` 的组合行为）；
   `mode = "auto"` 在小站点会退化为单索引，不受影响。
5. **测试夹具豁免**：`not-exist.png`（故意缺失图片）在两处检查中显式豁免并打印。
