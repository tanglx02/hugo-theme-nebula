## 二、P1 — 搜索结果日期 i18n（最后一个真实 UI 国际化缺陷）

### 缺陷
搜索索引 `date` 是机器格式 `2006-01-02`，前端直接渲染 `it.date`，导致三语言搜索结果
日期**全部显示为 `2026-09-28`**，而主题其他 UI 日期早已三语言本地化。

### 修复
- `layouts/_default/index.json` 新增 UI 字段 `dateDisplay`：
  `(cond .Date.IsZero "" (.Date.Format (i18n "common.dateFormat")))`
  —— 由 Hugo **在构建期**按站点语言生成，前端不猜语言、不重复实现格式化。
- `date` 保留为机器字段 `YYYY-MM-DD`（`(cond .Date.IsZero "" (.Date.Format "2006-01-02"))`）。
- 缺日期的文章两个字段均为空串，UI 省略日期片段（不显示 `0001-01-01` / `January 1`）。
- `assets/js/main.js` 搜索结果改用 `dateDisplay`（旧索引无该字段时才退回 `date`，向后兼容）。

### 测试（`tools/check_search_date.py`，30 项）
三语言真实构建（zh-CN / en / zh-TW）× 多篇文章 × 缺日期异常 ×
`date` 仍为机器格式 × JSON 结构向后兼容。**期望值由测试按 i18n 布局独立重算，不复用被测逻辑。**

| 语言 | `dateDisplay` 实测 |
| --- | --- |
| zh-CN | `2026年9月28日` |
| en | `Sep 28, 2026` |
| zh-TW | `2026年9月28日`（按 i18n 布局本地化） |

`check_date_format.py` 同步增加索引日期契约（`dateDisplay` 必须走 i18n；JS 禁止
`toLocaleDateString` / `Intl.DateTimeFormat`）。

### 顺带发现并修复的测试侧隐患
语言切换配置必须**复制到站点目录内**再用相对路径 `--config` 引用；直接引用站点目录外的
绝对路径会被 Hugo **静默忽略**，表现为"英文构建实际仍是中文"却无任何报错。

## 三、P2 — pagination crawler 判定修正

### 缺陷 1：article 判断过宽
`is_article_page()` 原用 `r"/[^/]+/[^/]+/"`，把 `/categories/linux/`、`/tags/hugo/`
等两级 term 页误判为文章页 —— 于是这些**可能产生分页的列表页被错误排除出 crawl 种子**。

**修复**：改为基于 `params.content.sections`（回退 `params.content.section`，再回退
`posts/tutorials/notes/projects`）判定：只有 `/posts/<slug>/` 等两级且首段属于内容
section 才是文章页。

### 缺陷 2（v1.0.8 遗留的隐藏假绿）
`discover_pagination()` 的种子**包含了分页页本身**，而分页页又被预置进 `visited`，
导致 crawler **什么都发现不了** —— v1.0.8 报告里 `DISCOVERED PAGINATION = 0` 正是这个
症状，却被误当成"全部已在 inventory"。修复为**种子排除分页页**，让交叉验证真正有意义。

### 测试（`tools/check_article_classification.py`，39 项）
posts / tutorials / notes / projects 文章页；categories / tags term；
`/page/N/`、`/categories/foo/page/N/`、`/tags/foo/page/N/` 均非文章页；
multi-section 分页；**crawler 发现结果 == 文件系统真值**（missing/extra 双向断言）。

### pagination.path 配置兼容
Hugo 支持可配置 `pagination.path`（实测确认）。crawler **从构建产物反推**当前路径片段，
再读配置，最后回退默认 `page` —— 不再永久写死 `/page/N/`。
测试覆盖 `pagination.path = "page"` 与 `= "p"` 两种构建。

## 四、P2 — alias 页面专项静态检查

`/page/1/` 等 alias 页本质是 meta-refresh 重定向，浏览器测试可能直接落到 canonical 页，
于是"审计 URL `/page/1/`"实际观察到的可能是目标页。本轮新增
`tools/check_alias_pages.py`（11 项）做**结构层**独立检查：

- 文件真实存在；每个都有**唯一** meta refresh 且带合法目标
- 每个都有且仅有 1 个 canonical；canonical 与 refresh 目标一致、无自引用
- refresh 目标在构建产物中真实存在
- 无额外 JS / inline 事件处理器；引用的本地资源均存在
- `lang` 合法且与站点语言一致；title 非空
- **空扫描保护**：若构建产物中找不到任何 alias 页 → FATAL（避免"检查失去对象"却假绿）

示例站点实测：`ALIAS PAGES = 83`，全部来自 inventory 的 alias 分类，11/11 通过。

Release 报告中据此**区分**「alias HTML 结构检查」与「普通 HTML 页面浏览器行为审计」。

## 八、门禁验证：七轮故意故障注入（本地 + CI 双向）

全部遵循「绿色基线 → 注入 → 本地 FAIL → GitHub Actions FAIL → 恢复 → 全绿」，
**未修改任何断言**。CI 侧失败 step 取证如下：

| 注入 | 内容 | 变红的门禁（CI 失败 step） | 本地 | CI Run |
| --- | --- | --- | --- | --- |
| A | 搜索结果日期硬编码 `2006-01-02` | Search date contract（+ Search edge cases） | exit 1 | `37823445976` |
| B | `is_article_page()` 退回宽泛正则 | Pagination crawler - article classification | exit 1 | `37824507137` |
| C | alias 去掉 meta refresh | Alias pages - static structure check | exit 1 | `37825222337` |
| D | `highlight()` 不做转义 | Search highlight - HTML entities & regex/XSS | exit 1 | `37825916193` |
| E | 回退 Node20 旧 action | Workflow policy（least privilege / pinned runner / Node24） | exit 1 | `37826520244` |
| F | 删除顶层 `permissions` | Workflow policy | exit 1 | `37827211532` |
| G | CI matrix 多加一个浏览器 | CI job inventory（+ 新增 msedge 的 Browser tests） | exit 1 | `37827911871` |

恢复基线后最终 CI：run `37828702977` → **success（10 job：9 执行 + 1 占位 skipped）**。

> **G 最有价值**：它证明 job 数量不是手写的死数字 —— 加一个浏览器后
> 「注释登记 3 != 实际 4」「TOTAL 注释 12 != 实际 13」立即判 CI 失败，
> 且新加的 msedge job 因无对应浏览器而真实报错。

### 注入工具自身的一个真实缺陷（已修复）

`inject_v109.py` 早期 `revert()` 对"删除型"注入使用 `str.replace("", old)`：
Python 会把 `old` 插到**每个字符之间**，把 `ci.yml` 从 483 行撑到 **58,902 行**
（E 轮还原时真实发生）。修复：删除型注入的还原改用 `git checkout HEAD -- <file>`
并断言基线锚点回归，绝不做 `replace("", ...)`。

### 另外三处本轮修复的工程缺陷

1. **按提交 SHA 找 CI run 必须过滤 `workflowName == "CI"`**：
   仓库里还有 `compat-latest.yml`，不过滤会先匹配到 `Compat latest` 的 run，
   把注入结果误记成 success；且下一轮 push 会因 concurrency `cancel-in-progress`
   取消上一轮的 CI run。
2. **注入驱动脚本必须放在仓库外**：放在 `tools/` 里会被 `git reset --hard BASE` 冲掉。
3. **Windows CRLF 假改动**：新增 `.gitattributes`（`* text=auto eol=lf` + 二进制白名单）统一 LF。
