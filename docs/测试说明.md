# 测试说明（v1.0.9）

本文件说明每个门禁**测什么、怎么跑、失败意味着什么**。所有脚本遵循
`tools/_testlib.py` 的退出码约定：断言失败、依赖缺失、浏览器启动失败、站点不可达、
零用例执行 —— 任何一种情况都 `exit 1`，不存在"打印 FAIL 但退出 0"。

## 2. Release 全站审计（关键门禁）

`audit.py` 在 `AUDIT_FULL=1` 时执行全站模式，**仅在 tag 推送或手动触发时运行**：

```bash
AUDIT_FULL=1 AUDIT_BROWSERS=chromium AUDIT_VIEWPORTS=320,375,768,1440 \
  python3 tools/audit.py http://127.0.0.1:8080
```

输出与断言（**真值来自构建产物 inventory，不是 sitemap**）：

| 指标 | 含义 |
| --- | --- |
| `PUBLIC HTML FILES` | 构建产物中的 HTML 文件数 |
| `FILESYSTEM EXPECTED URLS` | 由 inventory 推导的应审计 URL 集合 |
| `SITEMAP HTML URLS` | sitemap 中的 HTML 页面数（**仅作独立 SEO 索引检查**） |
| `MISSING URLS` / `UNEXPECTED URLS` | 两集合差集，任一非 0 即失败 |
| `DISCOVERY FAILURES` | 分页发现的抓取失败数，非 0 即失败 |
| `PAGINATION EXHAUSTED` | 队列耗尽且零失败 |
| `SITEMAP HTML PAGES` | （历史字段，保留）sitemap 中可审计的 HTML 页面数 |
| `PAGINATION CROSS-CHECK` | 构建产物中"可爬取分页页"的真值数量；别名分页页（`/page/1/`）不被链接，单独计数 |
| `DISCOVERED PAGINATION URLS` | 队列耗尽式爬取发现的分页数，必须等于上面的真值 |
| `PAGINATION MISSING` / `PAGINATION UNEXPECTED` | 真值与爬取结果的差集，任一非 0 即失败 |
| `PAGINATION PATH` | 当前分页路径片段：优先从构建产物反推，再读配置，最后用默认 `page` |
| `CRAWL SEEDS` | 参与爬取的列表页种子数（首页 / section 列表 / 分类 term / 标签 term / 归档） |
| `PAGINATION CRAWL ROUNDS` | BFS 实际轮数（仅记录，不是完成条件） |
| `PAGINATION CRAWL LIMIT` | 安全上限（`AUDIT_PAGINATION_LIMIT`，默认 10000） |
| `PAGINATION CRAWL` | `exhausted`（覆盖完整）或 `LIMIT REACHED`（**未完成，必须 FAIL**） |
| `AUDITED HTML URLS` | 实际进入审计的页面总数（等于 inventory 真值） |
| `SKIPPED INTENTIONAL ENDPOINTS` | 有意排除的非 HTML endpoint |

硬断言（任一不满足即 `exit 1`）：

1. 构建产物 inventory 100% 被审计（`EXPECTED == AUDITED`，差集任一非空即失败）；
2. **分页交叉验证**：所有可爬取的分页页都必须被 crawler 发现（`/page/1/` 别名分页页
   按设计不被链接，由 inventory 直接覆盖并单独计数）；
3. 分页发现零失败且**队列耗尽**（未达上限）；
4. crawl 种子覆盖首页 / section 列表页 / 分类 term / 标签 term / 归档页，且不含文章页；
5. 8 类必需页面齐全（分类 term / 标签 term / `/page/2/` / `/page/3/` / 分类首页 /
   标签首页 / 归档页 / 文章页）。

> 安全上限**只用于防失控**，不是覆盖目标：达到上限意味着"可能有未发现的分页页"，
> 判定为**未完成全站审计**并失败，绝不判 PASS。确需更大规模时调高 `AUDIT_PAGINATION_LIMIT`。

## 4. 门禁可信度验证（故意故障注入）

新增或修改门禁后，必须用**故意注入**证明它会真实变红：

| 注入方式 | 预期失败门禁 |
| --- | --- |
| 把 `AUDIT_PAGINATION_LIMIT` 压到低于真实分页数 | Release full-site audit（`LIMIT REACHED`） |
| 在 `discover_pagination` 中跳过某个 `/page/N/` | Release full-site audit（缺少必需页面类型） |
| 把评论语言写死 `zh-CN` | static-checks / Comments |
| 制造两个元素共用同一 `id` | static-checks / HTML quality |
| 去掉内容图片的 `alt` | static-checks / HTML quality |
| 搜索结果日期改成硬编码 `2006-01-02` | static-checks / Date format + Search date contract |
| 把 `is_article_page()` 改回 `/[^/]+/[^/]+/` | static-checks / Article classification |
| 删掉 alias 页的 meta refresh | static-checks / Alias pages |
| 把 `highlight()` 改成先替换再 esc | browser-tests / Search highlight |
| workflow 改回 Node20 旧 action | static-checks / Workflow policy |
| 删除 workflow 顶层 `permissions` | static-checks / Workflow policy |
| CI matrix 多加一个浏览器 | static-checks / CI job inventory（登记数量不再匹配） |

> 注意：GitHub Actions 中某个 step 失败后**后续 step 会被跳过**。若一次注入想验证多个
> 靠后的门禁，需要分多次提交分别验证，否则后面的步骤根本没有执行。

### 注入工具与驱动

- `tools/inject_v109.py`：A–G 七类注入的**应用与还原**。
  - 用法：`python tools/inject_v109.py A` / `... A --revert`
  - **删除型注入（new 为空）的还原走 `git checkout HEAD -- <file>`**，
    绝不能 `str.replace("", old)` —— 那会把锚点插到每个字符之间，
    把 workflow 撑到几万行（v1.0.9 真实翻车过）。
- `tools/run_ci_injections.sh`：CI 侧串行驱动（reset → 注入 → push → 等该 SHA
  的 **CI** workflow → 记录 → 恢复基线）。两个必须注意的点：
  1. 按 SHA 找 run 必须过滤 `workflowName == "CI"`，否则会先匹配到
     `compat-latest.yml` 的 run（它启动更早），把结果误记成 success；
  2. 每轮结束立刻恢复基线，否则下一轮 push 会因 concurrency
     `cancel-in-progress` 取消上一轮尚未完成的 CI run。
- 驱动脚本**放在仓库外**运行更安全（放在 `tools/` 里会被 `git reset --hard` 冲掉）。

v1.0.9 的七次注入（A–G）记录见 `docs/验收报告-v1.0.9.md`。

## 5. Modal 无障碍契约（所有浮层必须满足）

新增任何 modal（搜索、灯箱、未来的抽屉 / 弹窗）都必须通过
`createModalA11y`（`assets/js/main.js`）获得同一份契约：

| 要求 | 静态检查 | 交互测试 |
| --- | --- | --- |
| `role="dialog"` + `aria-modal="true"` + 可访问名称 | `security_baseline.py` | `verify_search_modal.py` / `verify_lightbox.py` |
| 打开时焦点进入首个可聚焦元素 | — | ✅ |
| Tab / Shift+Tab 在 dialog 内循环 | — | ✅ |
| 背景 `inert` + `aria-hidden` | — | ✅ |
| Escape 关闭 / 遮罩点击关闭 | — | ✅ |
| 关闭后焦点还给触发元素（无触发元素时退化为 dialog 自身） | — | ✅ |
| 快速重复开关幂等 | — | ✅ |
