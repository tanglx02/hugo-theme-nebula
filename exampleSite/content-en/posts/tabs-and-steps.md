This page demonstrates the second and third items of **feature 3 (technical content
components)**: **tabs** and **steps**.

Both are shortcodes, and neither needs JavaScript to show its content — without a
script the tabs component simply stacks every panel, and the step numbers come from
CSS.

## 1. Tabs: the same task on different platforms

The classic use case: one command, three systems.

{{< tabs >}}
{{< tab "Linux" >}}

Debian / Ubuntu:

```bash
sudo apt update
sudo apt install -y build-essential git curl
```

{{< /tab >}}
{{< tab "macOS" >}}

Install the Xcode command line tools first:

```bash
xcode-select --install
brew install git curl
```

{{< /tab >}}
{{< tab "Windows" >}}

PowerShell (winget recommended):

```powershell
winget install --id Git.Git -e
winget install --id cURL.cURL -e
```

{{< /tab >}}
{{< /tabs >}}

Every code block inside a panel carries the **language label** and a **copy button**
— that happens automatically because panels go through the theme's normal code-block
pipeline instead of an ad-hoc one.

## 2. Tabs: alternative install methods

{{< tabs >}}
{{< tab "Package manager" >}}

```bash
sudo apt install neovim
```

Pros: updated with the system, clean uninstall.

{{< /tab >}}
{{< tab "Official binary" >}}

Download the tarball for your architecture from GitHub Releases:

```bash
curl -LO https://github.com/neovim/neovim/releases/latest/download/nvim-linux-x86_64.tar.gz
sudo tar -C /opt -xzf nvim-linux-x86_64.tar.gz
sudo ln -sf /opt/nvim-linux-x86_64/bin/nvim /usr/local/bin/nvim
```

Pros: recent version, independent of the distro repositories.

{{< /tab >}}
{{< tab "Container" >}}

```bash
docker run --rm -it -v "$PWD:/work" -w /work alpine:3.20 sh
```

Pros: nothing pollutes the host, ideal for a throwaway environment.

{{< /tab >}}
{{< /tabs >}}

## 3. Steps: a complete procedure

Steps render as an ordered list (`<ol>`), and the numbers are generated by a CSS
counter — **no JavaScript**, and screen readers announce them as "N of M".

{{< steps >}}
{{< step "Prepare" >}}

Check the architecture and OS first so you install the right package:

```bash
uname -m && cat /etc/os-release | head -2
```

{{< /step >}}
{{< step "Install dependencies" >}}

```bash
sudo apt update
sudo apt install -y ca-certificates curl gnupg
```

{{< /step >}}
{{< step "Add the repository and install" >}}

```bash
curl -fsSL https://example.com/gpg | sudo gpg --dearmor -o /usr/share/keyrings/demo.gpg
echo "deb [signed-by=/usr/share/keyrings/demo.gpg] https://example.com/apt stable main" \
  | sudo tee /etc/apt/sources.list.d/demo.list
sudo apt update && sudo apt install -y demo-agent
```

{{< /step >}}
{{< step "Verify" >}}

A version string means success:

```bash
demo-agent --version
```

If the command is not found, go back to step 3 and check the repository URL and key
path.

{{< /step >}}
{{< /steps >}}

The step title is **optional** — omit it and only the number is shown:

{{< steps >}}
{{< step >}}

Look at the current state:

```bash
systemctl status nginx --no-pager
```

{{< /step >}}
{{< step >}}

Then decide whether to reload:

```bash
sudo systemctl reload nginx
```

{{< /step >}}
{{< /steps >}}

## 5. What happens without JavaScript

This is the core design constraint for these components: **content never depends on
the script**.

- **Tabs**: with no script the tab bar hides itself (so no button that does nothing)
  and every panel is stacked in order, each showing its own title. Disabling
  JavaScript therefore only removes the *switching* interaction — no content is lost.
- **Steps**: never needed a script; the numbering comes from a CSS `counter`.

Try disabling JavaScript and reloading this page to see it.

## 6. Keyboard and accessibility

When the script is available, tabs upgrade to the standard WAI-ARIA tabs pattern
(the W3C APG `patterns/tabs/` page — no outbound link here, so the example site
introduces no third-party request):

| Key | Action |
| --- | --- |
| `Tab` | Focus enters the tab bar (the whole bar is a **single** tab stop) |
| `←` `→` | Move between tabs and activate immediately |
| `↑` `↓` | Equivalent to left/right when the bar is stacked on narrow screens |
| `Home` `End` | Jump to the first / last tab |
| `Enter` `Space` | Handled by the native buttons |

State stays in sync through `aria-selected`, `aria-controls`, `aria-labelledby` and
the panel `hidden` attribute, so screen readers announce selection and panel
ownership correctly.

## 7. Print

When you print this page (or export it to PDF), **all panels are expanded** instead
of only the active one, interactive chrome such as the tab bar and copy buttons is
removed, and the step markers switch to high-contrast black and white.

## 8. Version compatibility

`tabs` / `tab` / `steps` / `step` are pure shortcodes plus CSS and behave identically
across every Hugo version the theme supports (from 0.128.0). Code blocks inside
panels use exactly the same rendering pipeline as regular code blocks.
